# GitHub Project Profile Instructions

This contract governs GitHub project profiles — showcase pages, repository summaries,
portfolio snapshots — for developers, maintainers, reviewers, and potential users evaluating
a project. The shared procedure is [document-authoring.md](document-authoring.md).

## Structure

1. `# Project Name`
2. `## Summary` — one short paragraph: audience, problem, and differentiator.
3. `## Problem and Audience`
4. `## Solution and Notable Choices`
5. `## Impact or Proof`
6. `## Links` — repository, demo, article, or talk.
7. `## Next Step` — invite the reader to try, review, or discuss the project.

## Writing Rules

- Lead with user value before implementation detail.
- Highlight only the technical choices that help a reader understand the project.
- Prefer concrete outcomes, lessons, or constraints over feature lists; keep any feature
  list short.
- Use short bullets for proof, notable choices, and links.
- State maturity honestly; say so when something is experimental.
- Word everything so it reads without internal company context.
